### Actionable Issue

**Video file_index hardcoded to 0 in reader** (medium severity)
- File: `crates/forge-formats/src/lerobot_v3/reader.rs:244`
- `resolve_video_path(video_key, chunk_idx, 0)` always opens `file-000.mp4`
- Writer produces per-episode MP4s (`file-000.mp4`, `file-001.mp4`, etc.)
- Reading back multi-episode output datasets reads wrong MP4 for episodes > 0
- Round-trip test passes because source uses single `file-000.mp4`
- Fix: pass `meta.episode_index % info.chunks_size` as file_index
- Affects: READ-03, VID-02

## Tech Debt Summary

### Phase 2: LeRobot v3 End-to-End Pipeline (5 items)

1. Field remapping is a no-op stub — `apply_field_remapping_static` discards `config.fields`. Deferred to Phase 5.
2. Multi-episode chunk video frame offset uses `frame_index` as-is — correct only for single-episode-per-MP4 layouts.
3. `force_keyframe_next()` implemented and tested but not auto-called at episode boundaries by writer.
4. `stats.json` written as empty `{}` placeholder.
5. Video `file_index=0` hardcoded in reader — incorrect for reading back multi-episode output datasets.

### Phase 3: Parallel Pipeline and Error Handling (3 items)

1. `ErrorCollector::should_stop()` not re-checked in sequential write loop (functionally correct, architecturally inconsistent).
2. `prefetch_episodes()` convenience wrapper exported but unused in production (only `prefetch_items` used).
3. Progress bar increments during remap phase, not write phase (semantics: "episodes remapped" not "episodes written").

**Total: 8 items across 2 phases**
