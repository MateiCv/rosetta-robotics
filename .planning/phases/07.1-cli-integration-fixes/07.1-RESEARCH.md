**Researched:** 2026-02-22

## Summary

Phase 7.1 addresses exactly 2 integration bugs found during the milestone audit and 1 tech debt item. All three issues are precisely identified with file/line references, root causes, and fixes that follow established patterns already used in other commands. No new libraries or architectural decisions are needed.

**Bug 1 (CLI-16):** `convert.rs` passes the raw `source` string directly to `Path::new()` at line 57 without calling `resolve_and_detect()`. This means `hf://` URLs are never resolved to local cache paths. Every other path-accepting command (inspect, quality, filter, stats, export-video) correctly calls `crate::output::resolve_and_detect(path)` as the first operation. The fix is to add the same call in `convert.rs` and pass the resolved path + detected format through to the `Converter`.

**Bug 2 (CLI-04):** `filter.rs` calls `forge_formats::get_writer(&format_name)` unconditionally on line 37, before checking whether `dry_run` is true. For read-only formats like "groot", `get_writer` returns `ForgeError::UnsupportedFormat`. The fix is to defer writer acquisition to only when it is actually needed (non-dry-run branch).

**Tech debt:** `output::print_table` is defined and exported but never called anywhere, producing a compiler warning. Remove it.

**Primary recommendation:** These are surgical 3-line to 15-line changes in well-understood files. A single plan with 3 tasks (one per fix) is sufficient.

## Architecture Patterns

### Pattern 1: resolve_and_detect Entry Point (CLI-16)

Every path-accepting CLI command MUST call `crate::output::resolve_and_detect(path)` as its first operation. This function:
1. Calls `hub_client::resolve_path()` which downloads hf:// URLs to local cache
2. Checks the resolved path exists
3. Calls `forge_formats::detect_format()` for auto-detection
4. Returns `(PathBuf, String)` -- resolved path and format name

**Commands that correctly use this pattern:**
- `inspect.rs` line 19: `let (resolved_path, format_name) = crate::output::resolve_and_detect(path)?;`
- `quality.rs` line 24: `let (resolved_path, format_name) = crate::output::resolve_and_detect(path)?;`
- `filter.rs` line 35: `let (resolved_path, format_name) = crate::output::resolve_and_detect(path)?;`
- `stats.rs` line 146: `let (resolved_path, format_name) = crate::output::resolve_and_detect(path)?;`
- `export_video.rs` line 24: `let (resolved_path, format_name) = crate::output::resolve_and_detect(path)?;`

**Command that DOES NOT use this pattern (the bug):**
- `convert.rs` line 57: `converter.convert(Path::new(source), ...)` -- raw string wrapped in Path

### Pattern 2: Deferred Resource Acquisition (CLI-04)

Resources that may not be available (like a writer for a read-only format) should only be acquired when they will actually be used. In `filter.rs`, the writer is only needed for the non-dry-run write path.

**Current (broken):**
```rust
// Line 35-37: Writer acquired unconditionally BEFORE dry-run check
let (resolved_path, format_name) = crate::output::resolve_and_detect(path)?;
let reader = forge_formats::get_reader(&format_name)?;
let mut writer = forge_formats::get_writer(&format_name)?;  // FAILS for "groot"
```

**Fix approach:** Move writer acquisition inside the non-dry-run branch, or only acquire when `!dry_run`.

### Pattern 3: FilterEngine Signature Consideration

The `FilterEngine::filter()` method signature is:
```rust
pub fn filter(
    &self,
    reader: &dyn FormatReader,
    writer: &mut dyn FormatWriter,  // Required parameter
    source: &Path,
    output: Option<&Path>,
) -> ForgeResult<FilterResult>
```

The writer parameter is required even though it is only used when `output` is `Some`. Two fix approaches:

**Approach A (CLI-level fix, recommended):** Conditionally acquire writer in `filter.rs`. For dry-run mode, create a no-op writer struct that satisfies the `FormatWriter` trait but does nothing. This keeps the `FilterEngine` API stable and avoids modifying `forge-quality` crate.

**Approach B (engine-level fix):** Change `FilterEngine::filter()` to accept `Option<&mut dyn FormatWriter>`. This is a bigger API change that would ripple to all callers and tests. Not recommended for a bug-fix phase.

**Approach C (simplest):** Acquire a default writable format's writer (e.g., "lerobot-v3") as a no-op stand-in for dry-run, since it will never be called. This avoids creating a new struct but is semantically misleading.

**Recommended: Approach A** -- a small `NopWriter` struct in `filter.rs` (4-5 lines) is clean, local, and obvious.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| hf:// URL resolution | Custom parsing in convert.rs | `crate::output::resolve_and_detect()` | Already exists, tested, handles all URL formats |
| Format detection | Manual format string matching | `forge_formats::detect_format()` via `resolve_and_detect` | Scored detection with ambiguity warnings |

## Common Pitfalls

### Pitfall 1: Converter Config vs resolve_and_detect Interaction
**What goes wrong:** `resolve_and_detect()` returns a detected format name, but `Converter::new(config)` may already have `config.source_format` set from CLI `--source-format` flag. If both are set, the Converter's internal `detect_format` call would be redundant.
**How to avoid:** When source_format is explicitly set via CLI, the Converter uses it. When not set, the Converter calls `detect_format` internally. The fix should pre-resolve the hf:// URL to a local path and pass the resolved path to `Converter::convert()`. The format detection inside the Converter will work on the resolved local path. Do NOT try to pre-detect the format and inject it -- let the Converter's existing logic handle detection from the resolved local path.

### Pitfall 2: NopWriter Must Satisfy FormatWriter Trait
**What goes wrong:** The `FormatWriter` trait requires `Send + Sync`. Any no-op writer must satisfy these bounds.
**How to avoid:** Use a simple unit-like struct: `struct NopWriter;` with trivial implementations. No interior mutability needed, so `Send + Sync` are auto-implemented.

### Pitfall 3: Don't Remove print_table Without Checking All Callers
**What goes wrong:** Removing a public function that might be used externally.
**How to avoid:** Grep confirmed `print_table` appears only at its definition site. No callers exist. Safe to remove entirely.

## Code Examples

### Fix 1: convert.rs -- Add resolve_and_detect (CLI-16)

```rust
// BEFORE (line 55-57):
let converter = Converter::new(config);
match converter.convert(Path::new(source), Path::new(output)) {

// AFTER:
// Pre-resolve hf:// URLs to local cache path.
let resolved_source = crate::hub_client::resolve_path(source)?;
let converter = Converter::new(config);
match converter.convert(&resolved_source, Path::new(output)) {
```

Note: We use `resolve_path()` directly rather than `resolve_and_detect()` because the Converter already handles format detection internally via `registry::detect_format()`. We only need the URL-to-local-path resolution.

### Fix 2: filter.rs -- Defer Writer Acquisition (CLI-04)

```rust
// BEFORE (lines 35-37):
let (resolved_path, format_name) = crate::output::resolve_and_detect(path)?;
let reader = forge_formats::get_reader(&format_name)?;
let mut writer = forge_formats::get_writer(&format_name)?;

// AFTER:
let (resolved_path, format_name) = crate::output::resolve_and_detect(path)?;
let reader = forge_formats::get_reader(&format_name)?;

// Only acquire a real writer for non-dry-run; use NopWriter for dry-run.
let mut real_writer;
let mut nop;
let writer: &mut dyn forge_formats::FormatWriter = if dry_run {
    nop = NopWriter;
    &mut nop
} else {
    real_writer = forge_formats::get_writer(&format_name)?;
    &mut *real_writer
};
```

With the NopWriter defined as:

```rust
/// No-op writer for dry-run mode where no output is written.
struct NopWriter;

impl forge_formats::FormatWriter for NopWriter {
    fn format_name(&self) -> &str { "nop" }
    fn write_episode(
        &mut self, _: &forge_core::Episode, _: &std::path::Path, _: usize,
    ) -> forge_core::ForgeResult<()> { Ok(()) }
    fn finalize(
        &mut self, _: &std::path::Path, _: &forge_core::DatasetInfo,
    ) -> forge_core::ForgeResult<()> { Ok(()) }
}
```
