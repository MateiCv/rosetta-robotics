  <name>Task 1: Fix hf:// URL resolution in convert command (CLI-16)</name>
  <files>crates/forge-cli/src/commands/convert.rs</files>
  <action>
Add `crate::hub_client::resolve_path(source)` call before `Converter::convert()` in `convert.rs`.

Currently line 57 does `converter.convert(Path::new(source), ...)` which wraps the raw CLI string as a filesystem path. For `hf://` URLs this produces a path-not-found error because the URL is never downloaded.

The fix:
1. Add `use std::path::PathBuf;` is NOT needed (Path is already imported and resolve_path returns PathBuf).
2. Before line 55 (`let converter = Converter::new(config);`), insert:
   ```rust
   // Pre-resolve hf:// URLs to local cache path (CLI-16).
   // We use resolve_path() directly rather than resolve_and_detect() because
   // the Converter already handles format detection internally.
   let resolved_source = crate::hub_client::resolve_path(source)?;
   ```
3. Change line 57 from:
   `converter.convert(Path::new(source), Path::new(output))`
   to:
   `converter.convert(&resolved_source, Path::new(output))`

Do NOT use `resolve_and_detect()` here -- the Converter already calls `detect_format()` internally. We only need the URL-to-local-path resolution from `hub_client::resolve_path()`.

Also update the `eprintln!` on line 52 to show the resolved path instead of the raw source string, by moving the resolve call before the print. Use `resolved_source.display()` in the format string.
  </action>
  <verify>
Run `cargo build -p forge-cli 2>&1 | grep -i error` -- should produce no errors.
Run `cargo test -p forge-cli` -- all existing tests pass.
Grep for `resolve_path` in convert.rs to confirm the call exists.
  </verify>
  <done>
`convert.rs` calls `hub_client::resolve_path(source)` before passing the path to `Converter::convert()`. An hf:// URL will be downloaded to local cache and the resolved local path used for conversion.
  </done>

<task type="auto">
  <name>Task 2: Fix dry-run writer acquisition in filter command (CLI-04)</name>
  <files>crates/forge-cli/src/commands/filter.rs</files>
  <action>
Defer `get_writer()` call in `filter.rs` so that read-only formats (e.g., "groot") do not error during `--dry-run`.

Currently line 37 calls `forge_formats::get_writer(&format_name)?` unconditionally, which fails for formats that have no writer (returning `ForgeError::UnsupportedFormat`).

The fix (Approach A from RESEARCH.md -- NopWriter):

1. Define a private `NopWriter` struct above the `run` function:
   ```rust
   /// No-op writer for dry-run mode where no output is written.
   struct NopWriter;

   impl forge_formats::FormatWriter for NopWriter {
       fn format_name(&self) -> &str {
           "nop"
       }

       fn write_episode(
           &mut self,
           _episode: &forge_core::Episode,
           _output_path: &std::path::Path,
           _episode_index: usize,
       ) -> forge_core::ForgeResult<()> {
           Ok(())
       }

       fn finalize(
           &mut self,
           _output_path: &std::path::Path,
           _dataset_info: &forge_core::DatasetInfo,
       ) -> forge_core::ForgeResult<()> {
           Ok(())
       }
   }
   ```

2. Replace lines 36-37 (the unconditional reader + writer acquisition) with:
   ```rust
   let reader = forge_formats::get_reader(&format_name)?;

   // Only acquire a real writer for non-dry-run; use NopWriter for dry-run
   // so read-only formats (groot) work with --dry-run (CLI-04).
   let mut real_writer;
   let mut nop;
   let writer: &mut dyn forge_formats::FormatWriter = if dry_run {
       nop = NopWriter;
       &mut nop
   } else {
       real_writer = forge_formats::get_writer(&format_name)?;
       &mut *real_writer
   };
   ```

3. Update the `engine.filter()` call (around line 60-65) to use the `writer` reference directly instead of `writer.as_mut()`:
   Change `writer.as_mut()` to just `writer` since it is already `&mut dyn FormatWriter`.

Add `use forge_core;` and `use forge_formats::FormatWriter;` to imports if needed (check existing imports first -- `forge_formats` is likely already imported via `forge_formats::get_reader`).
  </action>
  <verify>

Run `cargo test -p forge-quality` -- filter engine tests still pass.
Grep for `NopWriter` in filter.rs to confirm the struct exists.

`filter.rs` uses a `NopWriter` for dry-run mode, only acquiring a real writer via `get_writer()` when output will actually be written. Read-only formats no longer fail during `--dry-run`.
