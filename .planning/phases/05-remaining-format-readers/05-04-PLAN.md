<task type="auto">
  <name>Task 1: Implement Zarr reader with episode boundary support</name>
  <files>crates/forge-formats/src/zarr/mod.rs, crates/forge-formats/src/zarr/reader.rs, crates/forge-formats/src/lib.rs</files>
  <action>
1. Create `crates/forge-formats/src/zarr/` directory with `mod.rs`, `reader.rs`.

2. In `reader.rs`, create `ZarrReader` unit struct implementing `FormatReader`:
   - `format_name()` returns "zarr".
   - `can_read(path)`: check for `.zarr` directory extension, OR `.zarray`/`.zgroup` files in path, OR `data/` + `meta/` subdirectories with `episode_ends` array.
   - `inspect(path)`:
     a. Open Zarr store using `zarrs::storage::store::FilesystemStore::new(path)`
     b. Read `meta/episode_ends` array to determine episode count and total frames
     c. List all arrays under `data/` (e.g., `data/action`, `data/state`, `data/img`)
     d. For each array, read shape, dtype, chunk shape from `.zarray` metadata
     e. Build DatasetInfo: episode count = len(episode_ends), total_frames = last episode_end value
     f. Detect cameras: arrays with 3+ dimensions where last 3 dims look like (H, W, C) or (C, H, W) are image arrays
     g. Preserve all Zarr metadata (.zattrs) as dataset metadata
   - `read_episodes(path)`:
     a. Read `meta/episode_ends` array: cumulative frame counts per episode
     b. Compute episode boundaries: episode N spans frames [episode_ends[N-1]..episode_ends[N]] (first episode from 0)
     c. For each episode, read slices from each array in `data/`:
        - `data/action[start:end]` -> per-frame action LazyArray
        - `data/state[start:end]` or `data/obs[start:end]` -> per-frame state LazyArray
        - `data/img[start:end]` or `data/images/*[start:end]` -> per-frame LazyImage
     d. Use lazy loading: store the slice range and Zarr path in the closure, read chunk on first access
     e. For image arrays: detect encoding from data content (raw uint8 pixels vs compressed bytes). Use ImageEncoding::Raw for 3D uint8 arrays (H, W, C), ImageEncoding::CompressedBytes for 1D byte arrays.
     f. Preserve all unknown arrays (not action/state/image) as frame.metadata values
     g. Lenient reading: if a chunk is corrupt or missing, emit ReadWarning and skip the affected frames

3. Handle Zarr v2 specific details:
   - Read `.zarray` JSON for each array to get dtype, chunks, compressor, order
   - The `zarrs` crate handles v2 metadata parsing transparently (per research)
   - Blosc compressor is handled by zarrs default features (per research)

4. Implement `FormatDetector` for `ZarrDetector`:
   - Confidence scoring:
     a. `.zarr` directory extension: +0.4
     b. `.zarray` or `.zgroup` files found: +0.3
     c. `data/` + `meta/episode_ends` structure: +0.3
   - Evidence strings for each check

5. In `mod.rs`: re-export `ZarrReader` and `ZarrDetector`.

6. In `crates/forge-formats/src/lib.rs`: add `#[cfg(feature = "zarr-format")] pub mod zarr;`.

Per research: zarrs crate v0.23.3 supports Zarr v2 with "a V3 compatible subset of Zarr V2". Most robotics datasets (Diffusion Policy, UMI) use Zarr v2 with Blosc. The crate handles v2->v3 conversion transparently.

Per user decision: preserve original timestamps (step indices). Don't normalize.

<task type="auto">
  <name>Task 2: Add Zarr episode boundary computation and lazy slice loading</name>
  <files>crates/forge-formats/src/zarr/reader.rs</files>
  <action>
1. Implement helper `read_episode_ends(store: &FilesystemStore, root: &Path) -> ForgeResult<Vec<usize>>`:
   - Try reading `meta/episode_ends` Zarr array
   - If not found, try `episode_ends` at root level
   - Parse as int64 array, convert to Vec<usize>
   - If neither exists, treat entire dataset as single episode

2. Implement `compute_boundaries(episode_ends: &[usize]) -> Vec<(usize, usize)>`:
   - Returns (start, end) pairs for each episode
   - First episode: (0, episode_ends[0])
   - Subsequent: (episode_ends[N-1], episode_ends[N])
   - Validate: each end > start, ends are monotonically increasing

3. Implement lazy slice loading for arrays:
   - For each frame within an episode, create LazyArray closures that capture:
     a. The Zarr store path
     b. The array name (e.g., "data/action")
     c. The global frame index
   - On first load(), open the store, read the single-frame slice from the array
   - This avoids loading entire arrays into memory

4. Implement lazy image loading for image arrays:
   - Similar to array loading but produces LazyImage with ImageEncoding
   - For 3D uint8 arrays (H, W, C): ImageEncoding::Raw
   - For 1D byte blobs: check first bytes for JPEG/PNG magic, else CompressedBytes

5. Handle edge cases:
   - Datasets with no `meta/episode_ends`: single-episode fallback
   - Empty episodes (start == end): skip with ReadWarning
   - Multiple image arrays at different paths (e.g., `data/img`, `data/images/top`): detect all

6. Write unit tests for:
   - compute_boundaries with known episode_ends
   - Edge case: single episode (one element in episode_ends)
   - Edge case: empty episode_ends array
  </action>

`cargo test -p forge-formats --features zarr-format` passes all tests. Episode boundary computation is correct for various episode_ends arrays.
  </verify>
