       - `pub fn run(path: &str, output_dir: &str, episodes: Option<&str>, camera: Option<&str>, fps: Option<f64>) -> anyhow::Result<()>`:
         - Auto-detect format and get reader: `forge_formats::detect_format()` + `get_reader()`
         - Inspect dataset for camera info and FPS: `reader.inspect(Path::new(path))?`
         - Use dataset FPS or CLI override: `let video_fps = fps.unwrap_or(info.fps.unwrap_or(30.0));`
         - Read episodes: `reader.read_episodes(Path::new(path))?`
         - If `episodes` arg is specified (e.g., "0,1,5" or "0-5"), parse episode indices/ranges and filter
         - Create output directory: `std::fs::create_dir_all(output_dir)?`
         - For each episode:
           - Determine which cameras to export:
             - If `camera` specified, export only that camera
             - Otherwise export all cameras from the first frame
           - For each camera:
             - Collect all frames' images for this camera (resolve LazyImage to raw pixel data)
             - Use `forge_video::encode_frames()` or the encoder API to write frames to an MP4 file
             - Output filename: `{output_dir}/{episode_id}_{camera_name}.mp4`
           - Print progress: `eprintln!("Exported: {}", output_filename)`
         - Print summary: `eprintln!("Exported {} videos to {}", count, output_dir)`

       - `fn parse_episode_selection(spec: &str) -> anyhow::Result<Vec<usize>>`:
         - Parse comma-separated indices and ranges: "0,1,5" -> [0,1,5], "0-5" -> [0,1,2,3,4,5], "0,3-5,9" -> [0,3,4,5,9]
         - Error on invalid format

       - Important: Check the `forge-video` crate's public API to understand the encoder interface. The encoder likely takes raw frame bytes, width, height, fps, and output path. Read `crates/forge-video/src/encoder.rs` or `lib.rs` to understand the exact API signature. Wire accordingly — do NOT invent an encoder API that doesn't exist.

       - If forge-video does not expose a standalone "encode frames to file" function (it may only be used internally by the pipeline), then implement a minimal encoding wrapper:
         - Open an FFmpeg output context to the MP4 file
         - For each frame, send the decoded pixel data through the encoder
         - Close the output
         - This follows the same pattern as the pipeline's video writer but outputs to a standalone file instead of a dataset structure
