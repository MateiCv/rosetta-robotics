       - If `config_path` is Some, load base config via `ConversionConfig::from_yaml(path)?`
       - Otherwise use `ConversionConfig::default()`
       - Override ONLY when CLI args are explicitly set (use Option<T> for distinguishing):
         - `source_format`: override if Some
         - `target_format`: override if Some (keep default "lerobot-v3" if neither YAML nor CLI specifies)
         - `fps`: override if Some
         - `cameras`: extend (don't replace) — CLI camera mappings added on top of YAML cameras
         - `fail_on_error`: override if true (flag presence means true)
         - `deterministic`: override if true
         - `num_workers`: override if Some
         - `quiet`, `json_output`, `verbose`: override if true (flag presence)

    2. Update `crates/forge-cli/src/main.rs`:
       - Add `--config <path>` (Option<PathBuf>) arg to Convert command
       - Add `--source-format` (Option<String>) arg to Convert command
       - Change `--target-format` from `default_value = "lerobot-v3"` to `Option<String>` (config merge handles the default)
       - Update `run_convert()` to call `config::load_config()` instead of constructing ConversionConfig directly
       - Pass the resulting config to `Converter::new(config)`

    3. Implement field remapping in `crates/forge-pipeline/src/convert.rs`:
       - Replace the no-op `apply_field_remapping_static()` with actual logic:
       - For each entry in `config.fields`:
         - The key is the logical name, the value is `FieldMapping { source, target, transform }`
         - For each frame in the episode:
           - If `source` matches the frame's action field name (stored in metadata as "action_key" or similar): rename it to `target`
           - If `source` matches a metadata key in `frame.metadata`: remove old key, insert with `target` name
         - For field renaming, the primary cases are:
           - Action field renaming: The frame has `action: Option<LazyArray>` — this is a fixed field, not keyed. Field remapping for action/state operates through episode-level metadata renaming.
           - Metadata field renaming: Rename keys in `frame.metadata`
           - `transform` field: Log a warning "field transforms not yet supported, only rename" if transform is Some — defer actual transforms (normalize, clip) to future work per research recommendation
       - Keep camera remapping as-is (already working)

    Preserve all existing convert behavior. The field remapping only activates when `config.fields` is non-empty.
  </action>

  </verify>
