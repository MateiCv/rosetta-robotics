**Dependency setup:**
- Check if `ndarray` is an explicit workspace dependency in root `Cargo.toml`. If not, add `ndarray = "0.16"` to `[workspace.dependencies]` (the hdf5 crate's `with_data()` API requires `ndarray::Array`).

- Update the `hdf5-format` feature flag to include ndarray: `hdf5-format = ["dep:hdf5", "dep:ndarray"]`

**Create `crates/forge-formats/src/hdf5/writer.rs`:**

**HDF5Writer struct:**
- Fields: `layout: HDF5Layout` (enum: ALOHA or Robomimic -- reuse from layout.rs if it exists, otherwise define), `episodes_written: Vec<(usize, usize)>` (episode_index, frame_count), `deterministic: bool`
- Constructor: `HDF5Writer::new()` defaulting to ALOHA layout. Add `HDF5Writer::with_layout(layout)` for explicit layout choice.

**ALOHA layout write_episode (default, file-per-episode):**
- Create one HDF5 file per episode: `output_path/episode_{episode_index}.hdf5`
- Use `hdf5::File::create(path)` to create the file
- Write `/action` dataset: collect all frames' `frame.action.load()` into `ndarray::Array2<f32>` shape `[N, action_dim]`, write with `file.new_dataset_builder().with_data(&arr).create("action")`
- Write `/observations/qpos` dataset: collect `frame.state.load()` into `Array2<f32>` shape `[N, state_dim]`, write under observations group
- Write `/observations/images/{camera_key}` datasets: for each camera, collect decoded raw RGB frames into `ndarray::Array4<u8>` shape `[N, H, W, C]`. Images must be raw uint8 -- if source is JPEG/PNG encoded, decode first (pitfall 10). Write as uint8 dataset.
- Write episode metadata as HDF5 attributes on root group (episode_index, frame_count)

**Robomimic layout write_episode:**
- All episodes go into a single HDF5 file: `output_path/dataset.hdf5`
- Write under `/data/demo_{episode_index}/actions`, `/data/demo_{episode_index}/obs/joint_pos`, `/data/demo_{episode_index}/obs/{camera_key}`
- On first call, create the file. On subsequent calls, open with read-write mode and append groups.

**finalize implementation:**
- For Robomimic layout: write root-level attributes (total episodes, env metadata from dataset_info)
- For ALOHA layout: minimal -- each file is self-contained
- Track episode info for potential metadata writing

**set_deterministic:** Store flag.

**Tests (in writer.rs #[cfg(test)] mod tests):**
- `writer_aloha_layout`: Create 2 episodes with action (dim=4), state (dim=4), image (4x4 RGB). Write with ALOHA layout. Verify:

  - Verify `/observations/images/top` shape is `[5, 4, 4, 3]`
  - Verify data values match input within f32 precision
- `writer_round_trip_aloha`: Write with HDF5Writer, read back with HDF5Reader, compare episode data

Create `crates/forge-formats/src/zarr/writer.rs` implementing `FormatWriter` for Zarr v2 format.

**ZarrWriter struct:**
- Fields: `episodes_written: Vec<(usize, usize)>` (episode_index, frame_count), `episode_ends: Vec<u64>` (cumulative frame counts for episode boundary array), `deterministic: bool`, `action_dim: Option<usize>`, `state_dim: Option<usize>`, `cameras: Vec<(String, u32, u32, u8)>`
- Constructor: `ZarrWriter::new()`

**write_episode implementation:**
- On first episode: capture action_dim, state_dim, cameras from first frame (same pattern as v3 writer)
- Accumulate data across all episodes in memory-efficient way:
  - Append action data as `Vec<f32>` (flat, will reshape at finalize)
  - Append state data as `Vec<f32>`
  - Append image data per camera as `Vec<u8>` (raw, decoded from JPEG/PNG if needed)
  - Track `episode_ends` cumulative array
- NOTE: Zarr datasets are typically written all-at-once because the array shape must be known upfront. Buffer episode data and write arrays in `finalize()`. Since robotics datasets are typically < 1GB of numeric data, in-memory buffering is acceptable.

**finalize implementation:**
- Create Zarr v2 store: `zarrs::filesystem::FilesystemStore::new(output_path)`
- Verify zarrs output format: must produce `.zgroup` and `.zarray` files (Zarr v2), NOT `zarr.json` (Zarr v3). Check zarrs API for v2 mode -- may need `ArrayBuilder::with_metadata(zarr_v2_metadata)` or v2-specific store configuration (research open question 4). If zarrs defaults to v3, use manual `.zarray` JSON writing as fallback.
- Write root `.zgroup` metadata: `{"zarr_format": 2}`
- Write `data/action/.zarray` + chunk files: Create array with shape `[total_frames, action_dim]`, dtype Float32, Blosc LZ4 compression. Use `ArrayBuilder` with codec pipeline including Blosc.
- Write `data/state/.zarray` + chunk files: Shape `[total_frames, state_dim]`, dtype Float32, Blosc
- Write `data/img/{camera_key}/.zarray` + chunk files: Shape `[total_frames, H, W, C]`, dtype UInt8 (raw pixels, decode JPEG/PNG first per pitfall 10)
- Write `meta/episode_ends/.zarray` + chunk: Shape `[num_episodes]`, dtype Int64, containing cumulative frame counts
- Sort metadata JSON keys if deterministic

**Tests (in writer.rs #[cfg(test)] mod tests):**
- `writer_produces_zarr_v2_structure`: Create 2 episodes (3 frames each) with action (dim=4), state (dim=4). Write with ZarrWriter. Verify:
  - Root `.zgroup` exists with `zarr_format: 2`
  - `data/action/.zarray` exists with correct shape `[6, 4]` and dtype
  - `meta/episode_ends/.zarray` exists
  - Read episode_ends data, verify values are `[3, 6]`
- `writer_round_trip`: Write with ZarrWriter, read back with ZarrReader, compare episode data within f32 precision
