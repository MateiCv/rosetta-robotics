Create `crates/forge-formats/src/rosbag/writer.rs` implementing `FormatWriter` for ROS 2 MCAP format.

**CdrWriter helper struct** (either in writer.rs or add to ros2.rs if it makes more sense to co-locate with CdrReader):
```
struct CdrWriter { buf: Vec<u8> }
```
- `new()`: Initialize with CDR encapsulation header `[0x00, 0x01, 0x00, 0x00]` (little-endian)
- `align(n)`: Insert padding bytes to reach n-byte alignment boundary (pitfall 5)
- `write_u8(v)`: Append single byte
- `write_u32(v)`: Align to 4, write LE u32
- `write_i32(v)`: Align to 4, write LE i32
- `write_f32(v)`: Align to 4, write LE f32
- `write_f64(v)`: Align to 8, write LE f64
- `write_string(s)`: Write u32 length (including null terminator), then string bytes, then null byte
- `write_header(sec, nanosec, frame_id)`: Write ROS 2 std_msgs/Header (stamp.sec as i32, stamp.nanosec as u32, frame_id as string)
- `write_bytes(data)`: Write u32 length prefix then raw bytes (for byte arrays)
- `into_bytes()`: Return the buffer

**Helper functions for CDR encoding known ROS 2 message types:**
- `encode_cdr_image(image, frame_id, timestamp_ns)` -> Vec<u8>: Encode as `sensor_msgs/msg/Image` CDR:
  - Header (timestamp decomposed to sec/nanosec, frame_id)
  - height: u32, width: u32
  - encoding: string ("rgb8", "bgr8", etc.)
  - is_bigendian: u8 (0)
  - step: u32 (width * channels)
  - data: byte array (raw pixel data -- decode JPEG/PNG first if needed)
- `encode_cdr_joint_state(values, names, timestamp_ns)` -> Vec<u8>: Encode as `sensor_msgs/msg/JointState`
- `encode_cdr_float64_array(values, timestamp_ns)` -> Vec<u8>: Encode as generic float64 array for action/state data

**RosbagWriter struct:**
- Fields: `episodes_written: Vec<usize>`, `deterministic: bool`
- Constructor: `RosbagWriter::new()`

**write_episode implementation:**
- One MCAP file per episode: `output_path/episode_{episode_index:06}.mcap`
- Create `mcap::write::Writer` wrapping a BufWriter<File>
- **Register schemas** (pitfall 4 -- schemas must be registered before channels):
  - For each camera key: register `sensor_msgs/msg/Image` schema with encoding "ros2msg"
  - If action present: register action message schema (e.g., `std_msgs/msg/Float64MultiArray` or a custom type)
  - If state present: register state message schema (e.g., `sensor_msgs/msg/JointState`)
  - Store returned schema_ids
- **Register channels** for each topic:
  - Per camera: channel on `/camera/{key}/image_raw` with message encoding "cdr"
  - Action: channel on `/action`
  - State: channel on `/joint_states`
  - Store returned channel_ids
- **Write messages** for each frame:
  - Extract timestamp from `frame.metadata["timestamp_ns"]` as u64, default to `(frame_index * 33_333_333)` (30fps) if missing
  - For each camera image: CDR-encode with `encode_cdr_image()`, write via `writer.write_to_known_channel()`
  - For action data: CDR-encode action values, write to action channel
  - For state data: CDR-encode state values, write to state channel
- Call `writer.finish()` to close the MCAP file

**finalize implementation:**
- Minimal -- MCAP files are self-contained per episode
- Optionally write a manifest JSON listing episodes for convenience

  - Verify schema names are correct ROS 2 types

Create `crates/forge-formats/src/robodm/writer.rs` implementing `FormatWriter` for RoboDM EBML format.

**IMPORTANT CONTEXT:** The RoboDM EBML schema is undocumented (decision 05-07). The reader uses heuristic element classification with manually-discovered element IDs. This writer uses a "preserve and replay" strategy -- reconstruct EBML structure using element IDs stored in frame/episode metadata during reading. For data not originally from RoboDM, use best-effort heuristic element IDs. This writer has lowest confidence for interoperability (research note).

**EBML writing helpers:**
- `write_vint(buf, value)`: Write EBML variable-length integer (reverse of reader's `read_vint`):
  - 1 byte: 0x80 | value (for value < 0x80)
  - 2 bytes: 0x40XX (for value < 0x4000)
  - 3 bytes: 0x20XXXX
  - 4 bytes: 0x10XXXXXX
  - This encodes the VINT with width marker bits
- `write_element_id(buf, id)`: Write raw element ID bytes
- `write_element(buf, id, data)`: Write element_id + data_size_vint + data bytes
- `write_master_element(buf, id, children_data)`: Write container element wrapping children

**RoboDMWriter struct:**
- Fields: `episodes_written: Vec<usize>`, `deterministic: bool`
- Constructor: `RoboDMWriter::new()`

**write_episode implementation:**
- One .vla file per episode: `output_path/episode_{episode_index:06}.vla`
- Build EBML structure in memory, then write all at once:

1. **EBML Header:** Write standard EBML header element (ID 0x1A45DFA3) containing:
   - EBMLVersion: 1
   - EBMLReadVersion: 1
   - DocType: "robodm" (or from episode metadata if available)
   - DocTypeVersion: 1

2. **Episode container:** Write top-level container element
   - Check `episode.metadata` for preserved RoboDM element IDs (from reader's `ebml_element_ids` metadata)
   - If present, use those exact IDs to reconstruct the structure
   - If not present (cross-format conversion), use heuristic element IDs

3. **Per-frame elements:** For each frame, write:
   - Image elements: For each `frame.images`, write as binary data element. Use raw pixel bytes (decode if JPEG/PNG encoded). If original element ID is preserved in metadata, use it.
   - Numeric data: For action/state, write as binary f32 or f64 arrays. Pack values as raw little-endian bytes.
   - Text metadata: For string metadata values, write as UTF-8 element
   - Integer metadata: For integer values, write as big-endian integer element (EBML convention)

4. Flush buffer to file

**finalize implementation:**
- Minimal -- .vla files are self-contained per episode
- No top-level metadata file needed

**Tests (in writer.rs #[cfg(test)] mod tests):**

  - File starts with EBML header magic bytes (0x1A, 0x45, 0xDF, 0xA3)

- `writer_round_trip`: Write with RoboDMWriter, read back with RoboDMReader, verify:
  - Episode count matches
  - Frame count matches
  - Numeric data (action, state) preserved within f32 precision
  - Image dimensions match
