**Phase 1: Schema extraction (research)**

1. Examine the Python `robodm` library source code at https://github.com/BerkeleyAutomation/robodm to extract the EBML element ID mappings. Key files to investigate:
   - The VLA writer/reader Python code that defines EBML element IDs
   - Any `.ebml` schema definition files in the repo
   - The EBML header elements that identify the format version

2. If the Python source reveals the schema, create a constants module mapping EBML element IDs to semantic names:
   ```rust
   // Example (actual IDs from Python source):
   const ELEMENT_EPISODE: u64 = 0x...; // Episode container
   const ELEMENT_STEP: u64 = 0x...;    // Step/frame container
   const ELEMENT_IMAGE: u64 = 0x...;   // Video/image data
   const ELEMENT_ACTION: u64 = 0x...;  // Action array
   const ELEMENT_STATE: u64 = 0x...;   // State observation
   ```

3. If the schema cannot be fully extracted from the Python source, implement a **best-effort reader**:
   - Parse EBML container structure using `ebml-iterable` crate
   - Identify elements heuristically: large binary blobs are likely video/images, small numeric arrays are likely actions/states
   - Store all unidentified elements in metadata with their EBML element IDs as keys
   - Emit ReadWarning: "RoboDM schema partially unknown; some data stored as raw EBML elements"

**Phase 2: Implementation**

4. Create `crates/forge-formats/src/robodm/` directory with `mod.rs`, `reader.rs`.

5. In `reader.rs`, create `RoboDMReader` unit struct implementing `FormatReader`:
   - `format_name()` returns "robodm".
   - `can_read(path)`:
     a. Check for .vla file extension
     b. If directory: check for .vla files
   - `inspect(path)`:
     a. Open .vla file, parse EBML header to confirm format
     b. Count episodes by iterating top-level EBML containers
     c. Sample first episode to infer schema (action dims, image resolution, state dims)
     d. Build DatasetInfo with inferred fields and cameras
   - `read_episodes(path)`:
     a. Parse EBML structure using `ebml-iterable`
     b. Iterate top-level episode containers
     c. Within each episode, iterate step/frame elements
     d. For each step:
        - Extract image data as compressed bytes -> LazyImage with ImageEncoding based on content (RoboDM uses H.264/H.265 encoded streams, so likely CompressedBytes or a new H264 variant)
        - Extract action array -> LazyArray
        - Extract state/observation data -> LazyArray
        - All other EBML elements -> frame.metadata
     e. Lenient reading: if an episode's EBML structure is malformed, skip with ReadWarning

6. Implement `FormatDetector` for `RoboDMDetector`:
   - Confidence scoring:
     a. .vla file extension: +0.8 (unique to RoboDM)
     b. EBML magic bytes at file start: +0.2 (EBML files start with `0x1A 0x45 0xDF 0xA3`)
   - Evidence: ".vla extension", "EBML header confirmed"

7. In `mod.rs`: re-export `RoboDMReader` and `RoboDMDetector`.
8. In `crates/forge-formats/src/lib.rs`: add `#[cfg(feature = "robodm-format")] pub mod robodm;`.

**Risk mitigation:** If `ebml-iterable` crate proves incompatible with RoboDM's specific EBML variant, fall back to manual EBML variable-length integer parsing (VINT encoding). EBML is a well-specified binary format; the header parsing is straightforward even without a library.

Per research: confidence is LOW for this format. The implementation should gracefully handle partial understanding of the schema.
