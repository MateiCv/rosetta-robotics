<task type="auto">
  <name>Task 1: Implement ROS 1 and ROS 2 sub-format readers</name>
  <files>crates/forge-formats/src/rosbag/mod.rs, crates/forge-formats/src/rosbag/ros1.rs, crates/forge-formats/src/rosbag/ros2.rs, crates/forge-formats/src/lib.rs</files>
  <action>
1. Create `crates/forge-formats/src/rosbag/` directory with `mod.rs`, `ros1.rs`, `ros2.rs`.

2. In `ros1.rs`, implement ROS 1 .bag reading:
   - `read_ros1_bag(path: &Path) -> ForgeResult<Vec<Episode>>`:
     a. Open .bag file using `rosbag::RosBag::new(path)` or equivalent API
     b. Iterate over connections (topics) to discover available data
     c. Map known topic types to data roles:
        - `sensor_msgs/Image` or `sensor_msgs/CompressedImage` topics -> camera images
        - `sensor_msgs/JointState` topics -> robot state (joint positions/velocities)
        - `geometry_msgs/PoseStamped` or `geometry_msgs/Twist` -> state/action
        - All other topics -> metadata
     d. Group messages into frames by timestamp alignment:
        - Messages within a configurable time window (e.g., 10ms) belong to the same frame
        - Use the closest image timestamp as the frame anchor
     e. For Image messages: extract width, height, encoding from header, data as Bytes
        - If encoding is "rgb8" or "bgr8" or "mono8": ImageEncoding::Raw
        - If CompressedImage: ImageEncoding from format field ("jpeg" -> Jpeg, "png" -> Png)
     f. For JointState: extract position, velocity, effort arrays -> LazyArray
     g. One .bag file = one Episode (unless user-defined segmentation)
     h. Unknown message types: store raw bytes in frame.metadata as base64 or hex string with topic name as key
   - Per research: `rosbag` crate v0.6.3 handles bzip2/lz4 compression internally

3. In `ros2.rs`, implement ROS 2 MCAP reading:
   - `read_ros2_mcap(path: &Path) -> ForgeResult<Vec<Episode>>`:
     a. Open MCAP file using `mcap` crate: read the file into memory (or mmap), parse with `mcap::MessageStream::new(data)`
     b. Iterate messages in timestamp order
     c. For each message, check the channel's schema type:
        - `sensor_msgs/msg/Image`: deserialize CDR payload to extract image data
        - `sensor_msgs/msg/CompressedImage`: extract compressed bytes
        - `sensor_msgs/msg/JointState`: deserialize to get joint names, positions, velocities, efforts
        - `geometry_msgs/msg/PoseStamped`, `geometry_msgs/msg/Twist`: extract pose/twist data
     d. CDR deserialization: MCAP embeds schema in the file. For known types, manually parse the CDR payload (fixed layout):
        - CDR starts with 4-byte header (encapsulation scheme), then fields in declaration order
        - For Image: header -> height(u32) -> width(u32) -> encoding(string) -> is_bigendian(u8) -> step(u32) -> data(bytes)
        - For JointState: header -> name(string[]) -> position(f64[]) -> velocity(f64[]) -> effort(f64[])
     e. If `rosbags-rs` crate is available and provides CDR deserialization, use it instead of manual parsing. Check at implementation time if the crate exists on crates.io.
     f. If CDR deserialization fails for a message type, store raw bytes in metadata with a ReadWarning
     g. One MCAP file = one Episode
   - Handle ROS 2 SQLite3 bags (.db3 with metadata.yaml): detect from `metadata.yaml` presence, but ONLY support MCAP for actual reading. If .db3 detected, emit ReadWarning suggesting conversion to MCAP.

4. In `mod.rs`: re-export `ros1::read_ros1_bag`, `ros2::read_ros2_mcap`.
5. In `crates/forge-formats/src/lib.rs`: add `#[cfg(feature = "rosbag-format")] pub mod rosbag;`.
  </action>

  <files>crates/forge-formats/src/rosbag/reader.rs, crates/forge-formats/src/rosbag/mod.rs</files>
  <action>
1. In `reader.rs`, create `RosbagReader` unit struct implementing `FormatReader`:
   - `format_name()` returns "rosbag".
   - `can_read(path)`:
     a. If file: check extension is .bag, .mcap, or .db3
     b. If directory: check for .bag/.mcap/.db3 files, or metadata.yaml (ROS 2 bag directory)
   - `inspect(path)`:
     a. Detect sub-format: .bag -> ROS 1, .mcap -> ROS 2, .db3 -> ROS 2 SQLite (warn)
     b. For ROS 1: open bag, list connections/topics, report topic types and message counts
     c. For ROS 2 MCAP: parse MCAP summary section for channel schemas and message counts
     d. Build DatasetInfo: format "rosbag", fields from topic types, cameras from image topics
     e. Metadata: include all topic names, message counts, duration, start/end timestamps
   - `read_episodes(path)`:
     a. Detect sub-format from path
     b. If single file: delegate to `read_ros1_bag` or `read_ros2_mcap`
     c. If directory with multiple bag files: iterate files sorted by name, one Episode per file
     d. Lenient: skip unreadable files with ReadWarning
     e. Preserve original ROS timestamps in frame.metadata (per user decision: keep original timestamp form)

2. Implement `FormatDetector` for `RosbagDetector`:
   - Confidence scoring:
     a. .bag extension: +0.7 (very specific to ROS 1)
     b. .mcap extension: +0.6 (MCAP is also used outside ROS, slightly less specific)
     c. .db3 extension: +0.5 (SQLite could be non-ROS)
     d. metadata.yaml in directory: +0.3 (ROS 2 bag directory structure)
     e. For .mcap: check MCAP magic bytes (first 8 bytes: `\x89MCAP0\r\n`): +0.3
   - Evidence strings for each check

3. In `mod.rs`: re-export `RosbagReader` and `RosbagDetector`.

Per user decision: both ROS 1 and ROS 2 supported. Per research pitfall #4: for unknown message types, store raw bytes as opaque metadata.

  </verify>
